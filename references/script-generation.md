# 脚本生成规则

## 生成顺序

1. 建立“人群×场景×痛点×记忆点×证据形式”测试矩阵。
2. 先分配不同测试变量，再写开头，避免只换同义词。
3. 每条选择一个主框架和一个主指标；其他卖点只用于证明或异议处理。
4. 口播写完后反查镜头能否执行、道具能否获得、承诺是否被证据支持。

## 每条脚本字段

- 编号、记忆点、目标使用者/购买者、核心场景
- 钩子类型、预计时长、封面/标题
- 0–3秒开头、完整口播
- 分镜/画面、需采购或准备的道具
- 测试重点、主指标
- 沿用的爆款框架、底层逻辑
- 对应产品卖点、CTA

## 质量门槛

- 开头先说人和结果，避免从品牌、材质参数或空泛问候开始。
- 痛点写具体身体部位、动作、时间或后果。
- 证据至少包含三类中的两类：对比、测量/动作、结构微距/拆解。
- 口播与画面相互补充，不让画面只是重复念稿。
- 同批脚本覆盖关系、职业、地域、极端条件、破坏性证明、评论问题、多人证言等不同钩子。
- 测试重点写成可比较假设，不写“测试是否爆”。
- CTA匹配决策阶段：冷启动偏收藏/评论，强证据偏点击，综合款偏购买。

## 棚拍原则

- 用户户外不代表必须外景。用服装、职业道具、风、冰、雪、冷暖灯光表达场景。
- 棚拍可验证重量、尺寸、面料、结构、动作自由、吸湿等。
- 棚拍不可伪装真实零下温度、真实户外持续时长、未经检测的效果。
- 道具清单标注必买、建议买、可租和替代方案，优先复用高频道具。
