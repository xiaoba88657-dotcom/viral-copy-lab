# Obsidian 工作流

## 默认目录

```text
爆款研究/
├── 00-待拆解视频/
├── 01-单条案例拆解/
├── 02-品类爆款研究/
├── 03-爆款开头库/
├── 04-爆款框架库/
├── 05-产品脚本/
└── 99-已完成/
```

不存在时，仅在用户要求建立或保存时创建。不要移动用户既有文档，除非用户明确要求。

## 待拆解文档建议

```yaml
---
type: viral-video-inbox
product: 产品名称
status: 待拆解
created: YYYY-MM-DD
---
```

正文每条链接可附一行用户备注。提取时保留文件名、行号和备注。

## 输出路由

- 单条事实与观察 → `01-单条案例拆解/平台-账号-样本编号.md`
- 同品类跨样本结论 → `02-品类爆款研究/品类-爆款拆解.md`
- 开头原型与条件 → `03-爆款开头库/爆款开头库.md`
- 跨品类框架及成熟度 → `04-爆款框架库/爆款框架库.md`
- 新产品脚本、Excel → `05-产品脚本/产品名/`
- 原待拆解文件只有用户要求时才移动至 `99-已完成/`。

## 追加规范

- 新增内容包含日期、来源样本、适用品类/人群和证据等级。
- 旧结论变化时新增修订记录，不静默删除。
- 案例事实、跨样本规律和推断分别成段。
- Excel 保存在产品文件夹；Markdown 索引使用相对链接指向它。

## 调用示例

- `使用 $viral-copy-lab 拆解 Obsidian 中“爆款研究/00-待拆解视频/男士保暖裤.md”的全部链接。`
- `使用 $viral-copy-lab 把本轮新发现更新到爆款开头库，但不要覆盖旧版本。`
- `使用 $viral-copy-lab 根据品类研究和新品卖点生成30条脚本，保存到05-产品脚本。`
